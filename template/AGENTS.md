# 装修组件开发要求

- 右侧面板的每个配置项都必须对应实际元素或行为，并在修改后即时生效；不适用于当前布局、元素或状态的选项应隐藏，不能保留无效控件。
- 新组件的背景、边框、圆角、间距和阴影复用 `shared/componentStyle.js`；背景只保留一个生效来源。颜色同时支持自定义和主题绑定时，使用共用颜色控件，并同步更新 PHP 校验，保存主题引用而非当时的颜色快照。
- 使用 `shared/themeColors.js` 的预览变量及 `decorationTheme` 注入，保证浮层、预览与移动端使用当前页面的配色。布尔组件属性明确声明为 `Boolean`。
- 新增可跳转页面时同步加入 `admin/src/components/linkaddress` 的统一链接目录；含对象ID的页面必须让用户选择对应榜单或店铺，不能生成缺少必填参数的链接。推荐项复用统一页面选择器和链接解析逻辑。
- 验证必须包含真实面板操作、配置保存重载和移动端渲染/跳转，不能仅断言配置对象发生变化。按改动范围扩展 `tests/regression/decoration_controls_browser.cjs`、`decoration_controls_h5.cjs` 及 PHP 校验回归。
- 装修与 APP 同步验收必须使用实际保存的页面配置和当前商品数据，逐页覆盖首页、商城分类、购物车、商品详情、店铺和店铺分类。包含旧配置、店铺 ID 为 0、单规格、空活动/保障、导航继承/自定义/删除的场景；不能只用预设的完整测试数据。
- APP 截图必须滚动到本次修改的元素并人工检查；DOM 存在、图片请求成功或 APK 能启动均不能替代 UI 验收。图片还需验证响应 Content-Type、文件特征及实际解码尺寸；通过对外 API 路径验证部署后的图片链路。
- 明确区分页面名称与展示标题、继承导航与主动关闭导航；旧配置不得自动补出未配置的标题。验收报告分别记录源码测试、生产构建、Android UI、实际线上接口状态；隔离数据回放不得表述为线上部署验证。

具体约定见 `docs/decoration-component-contract.md`。
