# Android 启动与图片加载优化（2026-09-15）

本轮针对 Android 打开 App 到首页慢、首页出现后图片长时间保持占位图的问题。代码、App/H5 生产资源和隔离验证已完成；未部署服务器、生成新签名 APK、变更应用版本或执行数据迁移。

## 修改

- App 启动时提前请求首页装修配置，与开屏广告检查并行。结果只在内存中交给首次首页加载使用一次，最多保留 5 秒；账号、语言、预览主题不同则重新请求。失败可以正常重试，后续刷新继续读取当前配置。
- 图片组件移除内部重复的 `lazy-load`，避免与外层可见性控制及“加载前隐藏”相互等待。App 使用原生可见性观察加载临近屏幕的图片，支持嵌套滚动；冷启动 WebView 偶尔漏掉初次通知时，以一次 300 毫秒后的布局查询补齐首屏，离开组件会清理监听和定时器。
- 新 App 的本地 AVIF 显示地址增加 `format=auto`。浏览器通过 `Accept` 明确声明支持 AVIF 时返回上传文件的原始字节，不解码、不转码、不缩放；其余客户端使用 JPEG，不透明图片质量为 90、无色度抽样，透明图片保持 PNG。原始上传与素材库地址不变。
- Nginx 将已有 `/api/media/image` 地址直接转给图片服务，避免图片占用 PHP 业务进程。PHP 保留相同能力，兼容尚未更新 Nginx 的环境。同图并发转换合并，32 MB 内存缓存和最多两个转换任务的限制保留；缓存命中及传输不占转换名额。
- 图片响应包含 `Vary: Accept`、按实际响应字节生成的 ETag 和一天缓存，支持 304。旧 App 不带 `format` 的地址仍返回 PNG；新 App 配旧服务器时，旧服务器忽略额外参数，仍能显示原有 PNG。

格式协商依据浏览器的明确声明，不能仅按 Android 系统版本推断，`*/*` 也不代表支持 AVIF。参考 [HTTP 内容协商](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Content_negotiation)。

## 测量

公开线上样本：首页配置约 227 毫秒，原 AVIF 商品图 64,868 字节；原 `/api/media/image` 返回 476,125 字节 PNG，两次请求约 897/416 毫秒。这是开发机到线上服务的只读测量，并非用户手机测速。

同一商品主图通过真实发布 Nginx、隔离 Linux 图片容器测试：

| 返回内容 | 字节数 | 相对原 PNG |
| --- | ---: | ---: |
| 旧 App 的 PNG | 476,125 | 基准 |
| 旧内核的 JPEG | 178,011 | 减少 62.6% |
| 支持设备的原 AVIF | 64,868 | 减少 86.4% |

三种响应都实际解码为 1440 × 1440。AVIF 的 SHA-256 与源文件一致；JPEG 检查了实际显示效果。Windows 与 Linux AVIF 解码库生成的 PNG 字节略有差异，Windows 本地 PNG 样本为 484,539 字节，不混用两者计算比例。

Android 11 / WebView 83 上交替运行现有 6.0.16 资源与修改后资源，两组强制停止进程后冷启动。使用已保存的公开配置和图片、本地隔离 API；广告检查固定延迟 1000 毫秒、首页配置 700 毫秒，兼容图片响应设置固定传输延迟。不是线上网络验收，也不是修改前后所有运行成本的独立归因。

| 测量项（从发起启动计时） | 6.0.16 | 修改后 |
| --- | ---: | ---: |
| 首页内容进入渲染层 | 3.25 / 3.58 秒 | 2.63 / 2.65 秒 |
| 首屏图片全部解码且菜单图片解除隐藏 | 5.50 / 5.02 秒 | 4.76 / 4.77 秒 |

第二项包含首屏 10 张菜单图片和可见轮播等图片，不把隐藏的预加载节点已解码当作显示完成。截图在达标后再等待 400 毫秒并人工检查；保留早期只检查 DOM 解码的记录，但不计为最终显示结果。

- 源码：`home_prefetch.cjs`、`app_startup.cjs`、`app_home_startup.cjs`、`h5_lazy_images.cjs`、`request_completion.cjs`、`config_requests.cjs`、`app_decoration_consistency.cjs`、`storefront_frontend.cjs` 通过。覆盖首次消费、过期、身份/语言/主题隔离、失败重试、可见性与销毁、冷启动通知遗漏和旧环境回退。
- 图片服务：`media_display.py` 六项测试通过，覆盖透明度、尺寸、原图字节、源文件保护、并发转换、内存上限、HTTP 内容类型、304、Accept 与本地路径限制。两处 PHP 变更通过 PHP 7.4 语法检查。
- 传输：`media_delivery.cjs` 使用独立 Docker 网络、真实发布 Nginx 和 Linux 图片服务，另测 Windows PHP 回退。现代 Chrome 实际发送 AVIF Accept、收到 AVIF 并解码为 1440 像素。初轮因 Docker 内部网络端口不可达、测试 Request 未传入请求头、Playwright 简略请求头缺少 Accept 而失败；修正测试环境/读取方式后完整通过，保留失败记录。
- 构建：App 与 H5 生产资源构建通过，H5 保留已有大资源警告；未做签名 APK 打包。产物在 `.build/app-loading-20260915/app` 与 `h5`。
- H5 界面：当前生产构建的首次进入与刷新均显示 10/10 首屏菜单图片，浏览器没有页面脚本异常；使用相同公开配置回放，不改后台保存配置。
- Android：旧 WebView 实际验证首屏 10/10 菜单图、首页商品、分类、购物车及导航、商品详情/介绍/弹层、店铺及店铺分类。早期冷启动回放发现首次可见性通知遗漏，补充一次布局查询后重新通过。测试使用本地回放、临时网络隔离，结束后恢复模拟器原资源和网络规则。
- 未进行 iOS、小程序真机或部署后线上验证；目前用户手机上的已安装版本不会因此自动改变。

原始证据位于 `.build/app-loading-20260915/`：`delivery-results.json`、`media-benchmark.json`、`startup-results.json`、`android-results.json`、各次截图及 `builds.json`。首屏检查通过 `CRMEB_AUDIT_FIRST_SCREEN=1` 启用 `storefront_audit_native.cjs` 的实际图片显示断言；图片服务验证前置环境见 `services/media-display/README.md`。
