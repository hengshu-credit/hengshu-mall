# 商品品牌管理

后台入口：商品 → 商品品牌，`/admin/product/brand/list`。

后台页面加载时会重新获取菜单与权限，并更新侧栏及本地缓存；已有登录会话刷新页面即可看到新增且已授权的品牌入口。

品牌支持名称、标志图片、简介、排序、启停和适用范围。选择“通用”适用于所有分类；选择“指定分类”后可多选一级或任意细分类，选中分类覆盖其下级分类。多个范围按并集匹配。

添加／编辑商品的“基础信息 → 商品品牌”可搜索并多选，允许留空。先选择商品分类，候选品牌为通用品牌与匹配分类的启用品牌。切换分类时不会自动删除已选品牌，不适用项会显示提示，保存前需移除。已停用品牌不能用于保存商品；已关联商品的品牌禁止直接删除，可停用或先解除商品关联。

## 安装与更新

新安装由 `public/install/index.php` 自动加载 `upgrade/product_brands.sql`。已有实例更新代码后，首次读取后台菜单时自动补齐三张品牌表及菜单／权限；直接访问商品品牌接口时也会补齐缺失表（包括只缺关联表的情况）。也可在后台访问前主动执行：

```sh
php think product-brand:install
```

本地源码开发环境：

```powershell
docker exec -w /var/www crmeb_php php think product-brand:install
```

命令与自动初始化共用逻辑，可重复执行，使用当前数据库连接的表前缀，补齐缺失表、菜单及操作权限，并修复隐藏、软删除或父节点错误的品牌入口，保留已有菜单 ID 和商品数据。保存商品前完成建表，避免 MySQL 在商品事务中执行建表导致隐式提交。完成后刷新后台页面。子管理员需在角色权限中授予品牌列表和对应操作；商品编辑人员可直接读取品牌候选，无需拥有品牌管理权限。旧商品请求不传 `brand_ids` 时保留已有关系，传空数组表示清空。

其他服务器更新时须包含 `app/services/product/product/ProductBrandInstaller.php` 和 `upgrade/product_brands.sql`，并编译管理后台；数据库账号需有建表权限，否则先由具备权限的账号执行升级 SQL。

## 回归

`tests/regression/run-product-brands.ps1` 启动无外部网络、无宿主端口的临时 MySQL，使用实际 ThinkPHP ORM 与品牌服务验证分类规则、品牌关系、输入校验、事务回滚和安装重入，结束后删除临时容器。不会访问开发商城数据库。

回归还覆盖首次访问时自动安装、部分关联表缺失、菜单隐藏／父级错误、历史商品菜单标识、角色权限隔离和事务内禁止建表。`node --test tests/regression/product_brand_frontend.cjs tests/regression/modal_form.cjs` 验证侧栏更新、品牌多选和保障表单取消／关闭，以及保存失败后重试。
