# 满减活动后台配置

入口：营销 → 满减活动，路径 `/admin/marketing/full_reduction/list`。

参考：[Tigshop 满减活动后台](https://java-b2b2c-pro.tigshop.cn/admin/promotion/full-reduction/list)。已接通后台配置、购物车试算、订单自动扣减、商品行分摊及退款/拆单金额处理。普通商品按活动规则自动享受优惠，无需领取。

## 配置内容

- 活动类型：按金额 / 按件数；名称最多60字。
- 活动时间：精确到秒，支持1天、7天、15天快捷选择。
- 阶梯优惠：1至5级，可减价或打折，门槛按升序配置。
- 循环优惠：每满指定金额 / 件数减固定金额，仅一条规则。
- 金额最多两位小数；件数为正整数；折扣0.1至9.9折；金额满减的减免值必须小于门槛。
- 独立“适用商品”标签页：全部商品、指定商品、排除指定商品。支持名称 / ID、分类（含所有下级）、品牌、商品标签组合筛选；可单个/批量加入或剔除，清单支持单个恢复参与。筛选只用于找到商品，活动范围以明确选择的商品ID为准；预售商品不参与。
- 参与客户限制：指定会员等级，不选则不限制。
- 适用会员：全部会员，或按指定会员、会员标签、会员等级三种互斥方式选择。标签支持满足任一 / 满足全部。
- 排序默认50，数字越小越靠前；是否启用可在表单和列表修改。
- 列表支持活动名称搜索、状态筛选、分页、自定义排序、编辑、单条删除和批量删除。

活动状态依据服务端时间和启用状态计算：未开始、进行中、已结束、已停用；时间区间采用 `[起始时间, 截止时间)`。结束活动不可直接重新启用，需先修改截止时间。

同一商品在重叠时段内不能参加多个启用的满减活动；冲突校验覆盖全部、指定和排除商品范围，按商品和时间判断，不以会员圈选条件豁免。全部/排除范围也包含未来新增商品，所以两个开放范围即使当前没有共同商品也不能同时启用。保存与重新启用都会校验；事务内先锁定独立的单行锁记录，避免并发创建绕过冲突检查。

编辑时若已选商品或会员等失效，会保留其ID并显示失效提示，需移除或重新选择。批量删除采用事务和软删除，任一ID无效则整批失败。

## 安装与权限

在 `crmeb` 目录执行：

```sh
php think full-reduction:install
```

该命令及 `upgrade/full_reduction.sql` 可重复执行，支持自定义表前缀。首次后台导航请求也会补齐新表和菜单；全新安装程序已包含迁移。已有角色权限不会自动扩大，子管理员需分配满减活动查询、保存、启停、删除权限。

表：`store_full_reduction`、`store_full_reduction_mutex`（加项目表前缀）；升级命令还会幂等添加 `store_order.full_reduction_price` 金额字段。订单商品JSON存储该行满减金额、活动规则快照、优惠前单价、精确实付小计；历史订单缺失字段按零优惠兼容。

## 实际结算规则

1. 以服务端购物车/规格价格与数量为准，先应用原有会员价。
2. 仅选中的有效商品参与满减；秒杀、砍价、拼团、预售等专属活动商品不叠加满减。未选商品、被剔除商品不贡献门槛。
3. 阶梯优惠取满足门槛的规则中优惠金额最大的一档，不累加多档；循环优惠按完整门槛次数向下取整。件数按参与商品的数量合计，支持跨商品与SKU凑单。减免额最多为参与商品金额，不会产生负实付。
4. 折扣如8折为支付80%，对参与商品合计金额计算一次，并把最终应付金额四舍五入到分。
5. 满减后再校验优惠券门槛和适用商品金额，并将优惠券减免封顶到适用商品剩余金额；之后使用积分。运费按原有运费/包邮规则计算，不参与满减；礼物附加费也不参与满减。
6. 金额使用整数分 / BCMath 处理。满减、优惠券、积分分摊到商品行，总额保持精确一致；退款及拆单使用保存的 `sum_true_price`，不能使用显示用的两位小数单价乘数量反算。退货不重新计算剩余商品活动门槛，退回原商品行已分摊的实付款。
7. 每次试算都会读取当前活动、会员条件和商品有效状态。订单事务内再复核活动，若试算后发生变化则拒绝旧价格下单，提示重新确认。优惠券扣除、订单和库存写入在同一事务中，失败一起回滚。

购物车接口 `POST /api/cart/full_reduction_quote` 只接收 `ids`；不接受客户端商品价格或数量。拒绝其他用户、已支付、已删除、直接购买缓存或无效购物车ID。主购物车的勾选/数量变化会重新试算并忽略过期响应；试算失败或未完成时不能提交。分类页简易购物车也展示满减后的合计。确认订单及订单详情单独列出“满减优惠”。

## 本轮核对并修复的问题

- “部分会员”单选组仅监听 `change`、没有及时回写 `input`，实际点击后会回到旧值；已修复并加入真实DOM点击回归。
- 仅依赖当前商品库判断活动范围交集，会漏掉未来新增商品的冲突；改为范围集合判断。
- 通过编辑表单重新启用过期活动可绕过状态接口校验；已统一限制。
- 优惠券门槛、分摊、拆单和退款未考虑满减；已接入精确行金额。
- 原下单流程在事务外消耗优惠券，库存失败时无法恢复；改为事务内原子消耗。
- 快速切换商品或优惠券时，旧试算响应可能覆盖新合计；购物车和确认页均增加响应顺序校验。
- 确认页在无收货地址、无优惠券时不会触发试算，导致不显示满减；现进入确认页即计算商品优惠，地址选择后再计算运费。

接口前缀：`adminapi/marketing/full_reduction`。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `list` | 查询活动 |
| GET | `info/:id` | 详情及已选内容回显 |
| GET | `options` | 商品 / 会员 / 标签 / 等级选择器 |
| POST | `save/:id` | 新增（ID=0）或编辑 |
| PUT | `status/:id` | 启停，提交 `status` |
| PUT | `sort/:id` | 排序，提交 `sort` |
| DELETE | `del/:id` | 删除单条 |
| POST | `batch_delete` | 批量删除，提交 `ids` |

控制器显式验证新模块的接口权限，避免依赖旧版全局角色中间件的放行行为。会员选择接口仅返回ID、昵称、头像，不返回账户密码等字段。

前端回归挂载真实 Vue 与 Element UI 组件，覆盖配置校验、接口参数、跨页选择、异步请求乱序、详情回显、失败保留表单、重复提交、规则切换、列表过滤及删除。
