# 商户管理完整方案

版本：整合版 v1.0；日期：2026-09-11。状态：档案与商品归属阶段已实现，实际交付范围见[使用说明](/E:/workspace/CRMEB-merchant-management/docs/merchant-management.md)。本文保留后续交易阶段的设计。

## 1. 设计结论

将供应商管理与商户管理中的通用能力整合为一套“商户管理”：一个商户列表、一套资料表单、一套入驻审核、一处历史记录。

- 每一行是一个独立经营记录，统一称“商户”。企业主体是该记录的基础资料，不再提供主体／店铺视角切换。
- 商户类型是单选分类字典，预置自营、旗舰店、供应商，支持自定义。类型不决定销售、供货、权限、审核或结算规则。
- 商户不配置经营方式、上下游身份、销售／供货开关。具体合作关系记录在商品、合同或交易单据中。
- 同一家公司可按管理需要配置两条商户记录，例如品牌旗舰店和品牌供应中心；可复用主体资料，商品、账号权限及账目分别管理。
- 商品基础信息增加“所属商户”，直接选择统一商户档案。
- 商户基础资料保留主体身份、联系方式、结算账户、资质和电子合同。电子合同只需上传文件。
- 不设置签约授权、收件人、地址确认书、在线签署或独立核验台账。
- 审核操作和全部成功保存的信息修改统一进入“历史记录”，包括联系地址变化；记录由系统自动生成，无需手工填写变更登记。

本期重点是把商户建档、入驻、资料管理、商品归属和历史追溯做完整。采购、代发、跨店交易和结算沿用同一商户身份模型，按各自业务闭环分阶段接入。

## 4. 商户列表

### 4.1 查询与列信息

| 区域 | 内容 |
| --- | --- |
| 常用筛选 | 商户名称／编号、主体名称／信用代码、商户类型、标签、审核状态、经营状态 |
| 更多筛选 | 联系人／手机号、主账号、创建时间、证件到期、待补充资料 |
| 主列表 | 商户编号、名称与 Logo、主体名称、类型、标签、联系人及电话、主账号、商品数、审核状态、经营状态、创建时间 |
| 次要信息 | 最近审核人／时间、是否存在待审核资料修改，放在详情或展开信息中 |
| 行内操作 | 详情、编辑、查看商品；更多操作中放审核、账号权限、开业／暂停／恢复／关闭、导出资料 |
| 顶部操作 | 新增商户、按当前筛选导出；批量操作按权限开放，不对混合条件记录静默跳过 |

默认按创建时间倒序排列，支持分页。标签筛选按“命中任意已选标签”处理，筛选结果和导出结果使用相同规则。

商品数统计归属该商户的未删除商品，不将该商户参与的所有供货关联重复计入。主账号尚未配置显示“未配置”；尚未接入的交易指标不显示虚假的零值。

### 4.2 同主体多商户示例

| 商户名称 | 主体名称 | 商户类型 | 实际关联业务 |
| --- | --- | --- | --- |
| 平台商城 | 平台公司 | 自营 | 经营平台商品 |
| 某某品牌旗舰店 | 某某公司 | 旗舰店 | 经营品牌零售商品 |
| 某某品牌供应中心 | 某某公司 | 供应商 | 在具体商品或单据中与平台建立合作关系 |

三行使用完全相同的资料结构。最后一列用于解释场景，不是新增的经营方式字段。

主体按登记身份去重，商户按独立商户编号识别；不得用相同手机号、相似名称自动合并。复用主体资料必须检查账号权限，匹配信用代码不能使陌生账号取得该公司的资料。

## 5. 新增／编辑商户表单

采用一个分区表单，支持保存草稿、提交审核。系统自动生成编号、创建时间、修改时间和历史记录，不要求用户维护版本号。

### 5.1 基础资料

| 字段 | 规则 |
| --- | --- |
| 商户名称 | 必填，经营名称；与企业登记全称分别保存 |
| 商户编号 | 系统生成，唯一，不作为可编辑业务字段 |
| 商户类型 | 必选一项，来自启用的中性类型字典 |
| 商户标签 | 可多选，允许为空 |
| Logo、简介、备注 | 可选；备注仅后台可见 |
| 经营类目 | 需要限制商品发布范围时配置，判断依据为类目及资质，不是类型名称 |
| 主账号 | 可选；需要商户自行登录时绑定已有认证账号或使用正式账号开通流程 |
| 创建来源 | 系统记录平台创建、前台申请或导入等来源 |

商户名称建议同主体内避免重复；即使同名也必须通过编号区分，不能将名称作为关联键。

### 5.2 主体身份

“主体类别”是法律身份信息，与“商户类型”分开。企业为默认选项，个体工商户、自然人及其他组织按实际开放范围显示。

| 主体类别 | 核心身份资料 |
| --- | --- |
| 企业法人 | 登记全称、统一社会信用代码、营业执照原文件、登记住所、法定代表人姓名、职务和联系方式 |
| 其他组织 | 登记名称、适用登记号或信用代码、登记证明、住所、主要负责人姓名及联系方式 |
| 个体工商户 | 登记字号、信用代码、营业执照、经营者姓名、证件类别／号码、有效期、住址及联系方式 |
| 自然人 | 真实姓名、证件类别／号码、有效期、性别、出生日期、住所／常住地址、联系方式及必要身份证明 |

登记机关、成立日期、经营范围、营业期限等作为主体补充资料；营业期限支持“长期”，证件有效期按所提交证照记录。资料审核核对身份、证照与填写内容是否一致，意见进入历史审核记录。

不统一强制企业代表人提交身份证双面、手持照或人脸。自然人及个体经营者的证件材料按身份识别实际需要处理；不采集家属等无关资料。

### 5.3 地址与联系方式

| 字段 | 规则 |
| --- | --- |
| 注册地址／登记住所 | 已登记主体填写完整地址 |
| 实际经营地址 | 省市区＋详细门牌；与注册地址相同时可复用 |
| 联系人、联系电话 | 必填 |
| 邮箱、联系地址、邮编 | 按联系需要填写；可复用实际经营地址 |
| 客服电话 | 有消费者服务业务时填写，可与联系电话相同 |

保留当前有效的联系资料。无收件人字段、地址确认书或手工变更登记；任何地址修改自动写入统一历史。

### 5.4 结算账户

字段为户名、账户类型、开户银行、开户支行、账号。建档时允许暂缺，启用收付款前补齐并审核。平台人员在审核意见中记录账户归属问题，不另设账户核验台账。

默认按主体匹配的账户处理；例外情况由有权限的人员审核，不以账户户名自动替换合同相对方。账户修改审核通过前，业务继续使用原有效账户，不使用待审账户打款。

### 5.5 电子合同与资质附件

电子合同仅提供文件上传、预览、下载、替换和移除操作，支持多份文件。不增加协议编号、签署人、签署时间、签署证书、生效状态或在线签约字段。

- 文件名、上传人、上传时间、大小和存储引用由系统自动记录。
- 文件格式、大小由统一上传配置限制；预览失败仍能受控下载原文件。
- 营业执照、行业许可、品牌授权按各自类别保存，适用要求依据具体主体及商品。
- 每次提交审核固定当次文件集合，替换文件不能覆盖旧提交、旧审核或交易引用的原文件。
- 文件从当前资料移除会记录变化；已有历史引用的原件继续按保存策略保留。

外部合作商户开业前应上传电子合同；平台自身的内部经营记录不要求与自己签合同，也不生成虚假合同附件。

## 6. 商户类型与商户标签

| 规则 | 商户类型 | 商户标签 |
| --- | --- | --- |
| 用途 | 中性分类 | 运营标记 |
| 选择 | 单选，必填 | 多选，可空 |
| 预置示例 | 自营、旗舰店、供应商 | 可由平台按需创建 |
| 维护字段 | 名称、说明、排序、启用状态、是否允许入驻申请选择 | 名称、颜色、说明、排序、启用状态 |
| 新增／编辑 | 支持；去除首尾空格后名称不重复 | 支持；名称不重复 |
| 停用 | 不再提供新选择，已有商户可保留 | 不再提供新选择，已有标记保留显示 |
| 删除 | 有商户或未结束申请引用时禁止删除 | 有商户引用时禁止删除 |
| 业务影响 | 不改变身份、权限、商品归属、审核及结算 | 不改变身份、权限、商品归属、审核及结算 |

历史中冻结类型和标签的 ID 及当时名称。字典改名不能使旧记录变成新名称；字典操作自身也留记录，当前商户展示受影响时能够追溯到该字典修改。

类型中的“自营”文字不授予平台身份。消费者端是否展示自营，依据实际经营主体和平台所属关系确定；该关系由平台内部配置维护，不增加商户自营认定表单开关。

## 7. 入驻申请、资料修改与状态

### 7.1 两个进入方式

**自主入驻：** 登录申请账号 → 填写资料及上传文件 → 提交 → 平台审核 → 创建商户记录 → 待开业 → 满足条件后开业。

**平台创建：** 后台新增 → 保存资料 → 平台审核 → 待开业。拥有审核权限的人员可在详情中完成审核，仍产生审核记录，不把“平台录入”当成已核实全部资料。

同一公司增加另一条商户记录仍使用同一入口，可复用有权使用的主体资料。审核通过前不能仅因信用代码相同而绑定其主账号或开放已有商户权限。

### 7.2 申请页与流转

申请列表展示申请单号、申请商户名称、主体、类型、联系人、提交时间、状态、审核人、审核时间。支持按名称、类型、申请状态和提交时间筛选。

申请状态：草稿、待审核、待补充、已通过、已驳回、已撤回。

- 草稿保存后有记录；提交后形成不可变提交快照。
- 待审核可通过、驳回、要求补充；申请人可撤回。
- 驳回、待补充、撤回后可修改并再次提交，保留前次记录。
- 待审核内容不能被覆盖；需要修改时先撤回或转待补充。
- 驳回和要求补充必须填写意见，审核通过可填写备注。
- 重复点击、网络重试或同时审核，只能产生一次开通结果。

初次通过时，在事务内关联主体、建立商户、关联文件、绑定已确认的账号权限并写入历史；任何一步失败均不留下半开通记录。通知失败单独重试，不重复创建商户。

### 7.3 商户经营状态

| 状态 | 允许的行为 |
| --- | --- |
| 待开业 | 维护资料、配置账号、准备商品草稿 |
| 营业中 | 在审核及权限范围内开展业务 |
| 暂停营业 | 停止新业务，保留资料维护、已有订单履约、售后和对账 |
| 已关闭 | 保留历史查询及必要的存量业务处理；重新开业须满足资料与业务条件 |

审核状态回答资料是否通过，经营状态回答商户当前是否开展业务，二者不互相覆盖。审核通过不会自动上架商品，也不会自动恢复已暂停商户。

平台默认商户在承担默认归属时不能关闭或删除，须先切换到另一条正常的平台内部商户记录。有商品、申请、历史或交易引用的记录采用关闭／归档，不能物理删除历史。

### 7.4 信息修改与生效

| 修改范围 | 建议生效规则 | 留痕 |
| --- | --- | --- |
| 名称、Logo、简介、备注、类型、标签、联系人、电话、邮箱、联系地址 | 有权限者保存即生效 | 所有实际变化记录前后值 |
| 主体登记身份、法定代表人／经营者、证照、账户、电子合同、影响经营资格的资料 | 保存到待审资料，审核通过后生效 | 保存、提交、审核分别记录阶段 |
| 开业、暂停、恢复、关闭 | 按对应操作权限及业务条件立即处理 | 前后状态及已有操作原因 |
| 平台默认商户、账号权限 | 按相应平台管理权限处理 | 记录变更对象、操作者及结果 |

资料当前值与待审资料分开存放。已有商户提交核心资料修改时，页面展示“现有资料已生效／有待审核修改”；业务继续引用原有效资料。新资料被驳回，不覆盖原有效资料。原资料本身已失效时，按失效原因限制新业务，不能依靠“正在审核”延长效力。

共享主体的变更按一次变更申请确定影响范围，审核通过时统一更新该范围并在各商户历史中关联同一事件。审批前若主体版本或关联范围已改变，要求重新确认提交，避免漏记受影响商户。更换为另一法律主体须建立新的主体关联和明确的业务处理，不用修改公司名称覆盖旧交易主体。

## 8. 历史记录

商户详情只有一个历史入口，汇总创建、信息修改、附件调整、状态操作、提交／撤回、审核等事件。支持按事件类型、操作者和时间筛选，按时间倒序展示。

| 字段 | 内容 |
| --- | --- |
| 操作类型 | 创建、修改、附件调整、状态操作、提交、撤回、审核 |
| 操作人 | 实际账号和姓名；系统操作明确显示系统及来源 |
| 操作时间 | 系统生成的发生时间 |
| 操作摘要 | 本次影响的字段或审核结论 |
| 修改详情 | 字段名称、修改前值、修改后值 |
| 附件变化 | 新增／移除／替换的文件名称与前后文件引用 |
| 审核详情 | 结果、意见、当次提交资料和文件 |
| 阶段及来源 | 草稿、待审、已生效；后台、商户端、导入或系统 |

示例：

```text
09-11 15:20  修改资料  张某
联系电话：138****1234 → 139****5678
联系地址：杭州市…… → 宁波市……

09-11 16:10  替换电子合同  李某（待审资料）
合作合同-A.pdf → 合作合同-B.pdf

09-11 17:00  审核通过  王某
关联本次提交资料及合同-B.pdf；合同-A.pdf 仍可在历史中查看
```

实现规则：

1. 只要成功保存且内容发生变化就记录，不能只记需要审核的改动；类型、标签、所有地址和账户同样覆盖。
2. 一次保存的字段及附件变化合并为一个事件，独立附件操作单独记。审核引起的状态变化包含在审核事件内，避免重复行。
3. 前值取数据库实际旧值，后值取校验后的最终保存内容，操作者和时间由服务端确定；不信任客户端提交的日志内容。
4. 资料变更与记录写入同一事务；记录失败则资料修改回滚。取消、失败或无变化保存不记为成功修改。
5. 并发保存进行版本检查，重复请求使用事件标识防重；日志中的前后值必须与实际版本相符。
6. 保留创建基线、提交快照和变化记录，可追溯任一历史版本。普通后台不能修改或删除记录，不提供直接覆盖式历史回滚。
7. 历史文件保留原件及引用；从当前表单移除不等于删除旧文件。账号、手机号、证件和账户在历史及导出中按同等权限脱敏。
8. 共享主体事件冻结当时受影响的商户范围，后来新增或解除关联的商户不被误算为当时受影响对象。
9. 类型／标签及操作者名称在事件中保存当时展示值，后续改名不改写旧记录。
10. 信息变更留痕由系统完成，不恢复签约授权、收件人、地址确认书或手工变更说明等已移除字段。

## 9. 商品关联与供货关系

### 9.1 商品归属

商品基础信息增加：

```text
所属商户 *  [请选择商户 ▼]
```

候选按商户名称、编号、主体名称搜索，展示名称、类型和主体以便区分。平台新增默认使用平台默认商户；商户账号新增时由服务端限定在其有权管理的商户内。

商品列表增加所属商户、商户类型和主体名称，可筛选、查看关联资料和按权限导出。商品新增、编辑、详情、草稿、复制、采集、批量导入／更新必须使用一致的归属规则。

- 一个零售商品只属于一个商户；同款由两条商户记录经营时，建立两条商品记录，价格、促销和销量分别维护。
- 候选不按“供应商／旗舰店”等类型排除；按审核、状态、资质和账号权限判断可用性。
- 待开业商户可准备草稿；上架、购买和结算时需要检查实际经营条件。
- 关联失效时保留原商户名称及原因，不自动归到平台商户。
- 未上架、无订单及活动引用的草稿可由有权限者调整归属；已进入业务的商品通过复制到目标商户建立新商品，历史归属不动。
- 类型、标签修改不改变商品归属，也不自动变成商品标签。

### 9.2 具体供货场景

商户向平台提供货源时，在可选商品货源资料或采购／代发单中记录对方商户、所依据的电子合同和相关 SKU。两个参与方都引用统一商户档案，不增加供应商主表或上下游开关。

| 场景 | 所属商户 | 其他关联 | 业务处理 |
| --- | --- | --- | --- |
| 品牌直接经营商品 | 品牌商户 | 可无 | 对外订单归品牌商户 |
| 平台采购后销售 | 平台商户 | 采购来源商户和合同 | 平台验收入库、管理已取得的销售库存 |
| 平台销售、合作方代发 | 平台商户 | 当笔供货／履约商户、合同及 SKU | 对外订单归平台，内部生成履约任务 |

货源未填写显示“未记录”，不推定为自有货源。首期商品货源可先按一条对方关系记录，复杂 SKU 多来源及自动切换后续扩展。

复制商品不复制可销售实物库存；同公司两条商户记录若共用仓库，要明确共享库存源和预占机制。采购入库后，对方停用不妨碍平台销售已取得库存；代发关系失效时阻止依赖该关系的新交易，存量订单继续协调处理。

## 10. 订单、往来账与资料追溯

商户记录保持中性，但业务单据必须明确当笔交易各方、合同、商品、履约和金额。

- 零售订单按商品所属商户划分；跨店一起支付时使用支付分组，保留各商户的订单及金额分摊。
- 店铺优惠只作用于相应商品；平台优惠、运费和退款分摊固定到明细，明细、子订单与支付总额相等。
- 采购入库按采购验收形成相应往来；代发按履约及约定形成往来。不能因消费者每次购买，重复计算已经采购入库的货款。
- 同一商户可能有不同性质的往来，按单据分别记录，不用一笔净余额代替来源明细。
- 订单保存交易时的主体资料、商户归属、合同文件引用、SKU、价格、费用规则、优惠和履约信息快照。后续资料修改不反推历史。
- 消费者退款、合作方退货和采购应付调整分别处理，不用一个退款状态自动认定全部责任。

资料包按商户、合同、订单范围和截止时间生成，包含基础资料、电子合同、审核与修改历史、订单、支付退款、物流签收、验收、对账及相关沟通资料。保留文件原件和可检查的来源，未取得的资料如实标缺，不补造记录。

商户基础信息用于识别对方，不能独立代替具体案件的诉讼请求和交易证据。案件所需材料由实际争议决定，系统不显示“保证可起诉／胜诉”。主体明确性可参考[最高法关于被告身份信息的答复](https://www.court.gov.cn/zixun/xiangqing/184581.html)，电子资料留存参考[民事诉讼证据规定](https://www.court.gov.cn/zixun/xiangqing/212721.html)。

## 11. 权限、停用与文件保存

| 权限 | 可操作范围 |
| --- | --- |
| 商户资料维护 | 查看和修改获授权商户资料 |
| 商户审核 | 查看提交资料，执行通过、驳回、要求补充 |
| 历史查看 | 查看获授权商户的记录，敏感值按另行权限控制 |
| 类型／标签管理 | 管理分类字典，不因此获得商户账户原件权限 |
| 商品维护 | 读取必要商户候选、维护获授权商品 |
| 账户资料查看／维护 | 查看或调整银行资料，操作独立留痕 |
| 原文件查看／下载 | 受控访问证照和电子合同 |
| 资料导出 | 导出授权范围内资料和历史，不自动发送给第三方 |

账号权限和商户分类分开。一个账号可管理多条商户记录，切换后所有查询、缓存、统计、附件和导出都要重新校验范围，不能只在界面隐藏按钮。

暂停商户时统一阻止新业务：商品列表、详情直达、推荐、活动、购物车、下单和支付前均应用有效性检查。保持商品原有上／下架意图，恢复商户不把原本下架商品自动上架。已支付订单保留履约、售后及对账路径；支付回调并发时按实际结果处理，避免扣款后丢单。

身份证件、银行账户和合同使用私有存储、脱敏展示和受控下载，日志中不记录密码、令牌等认证秘密。文件校验值用于检查一致性，不单凭它认定文件真实性。

平台内经营者身份信息、商品与交易信息的保存期限分别设置：身份信息至少保存至退出平台后三年，交易信息至少保存至交易完成后三年，另有规定时从其规定；有关争议的材料在必要范围内设置保全，普通关闭操作不触发删除。依据：[网络交易监督管理办法第 31 条](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2025/art_4b47c79b8d994a42bba4835997688faa.html)。敏感信息收集和保留按目的必要性及合法处理依据执行，参见[个人信息保护法](https://www.samr.gov.cn/wljys/gzzd/art/2023/art_3ef1e889c1e644d4b65b5f5c7f432386.html)。

必要的类目／品牌资质关联复用或扩展既有模块。供货关系和采购／代发实体在相应阶段建立，不在商户表中加入 business_mode、上游／下游标记或销售／供货开关。

商品新增 seller_shop_id 表示“所属商户”。虽然技术字段保留 shop 命名，界面一律显示商户；既有 store_id 继续表示线下自提门店。

数据一致性要求：

1. 商户编号、主体有效身份标识、类型名称及关系键按各自业务规则唯一。
2. 商户资料、共享主体、账户使用版本校验；不能只校验商户行而漏掉共享主体并发。
3. 提交和批准使用明确的快照版本；新建申请通过只创建一次商户，资料变更通过更新既有商户。
4. 历史事件幂等键唯一，变更、事件、影响范围在同一事务提交。
5. 证件号码等字段加密存储；查重采用受控索引，敏感前后值也执行同等保护。
6. 草稿与有效资料分开，待审合同或账户不成为正在履约订单的实际依据。

## 15. 实施范围与验收

### 15.1 开发顺序

| 阶段 | 交付内容 | 完成边界 |
| --- | --- | --- |
| A：商户档案与商品归属 | 四个菜单、统一表单、类型标签、电子合同上传、入驻与变更审核、完整历史、商品选择和旧数据迁移 | 商户可建档、审核、关联商品；不宣称已完成外部商户独立交易 |
| B：商户交易 | 账号与数据隔离、商品审核、归属展示、跨店订单、优惠运费分摊、售后、对账和交易资料包 | 交易闭环验收通过后开放外部商户销售；人工结算也需可核对记录 |
| C：供货执行 | 可选商品来源、采购验收入库、代发、SKU 映射、库存预占、履约及往来账 | 各供货方式单独验收后开放；不因填了关联商户就启用自动供货 |

保证金、在线签约、自动分账、复杂供应链及跨平台对接不作为首期隐含交付。具体业务方向在单据中表达，三个阶段始终共用中性商户档案。

### 15.2 核心验收场景

1. 列表只有一个经营记录视角；同主体两商户可复用资料，各自拥有类型、标签和商品。
2. 自营、旗舰店、供应商及自定义类型都可使用同一表单，类型改名／停用不改变经营角色。
3. 表单没有经营方式、上下游、签约授权、收件人、地址确认或在线签署字段。
4. 电子合同可上传、预览、下载和替换；旧文件可从历史和旧审核中受控查看。
5. 公司、个体及自然人按相应身份资料审核，联系人不自动当作法定代表人。
6. 平台直接编辑、商户编辑、导入、系统变更均留痕；一次保存多个字段合并一条事件。
7. 取消、失败、无变化和请求重试不会生成错误或重复成功记录；日志失败回滚资料。
8. 普通修改即时生效并记录前后值，核心修改经审核生效，驳回不覆盖原有效账户／合同。
9. 共享主体变更的影响范围及版本准确，所有当时受影响的商户可查同一事件。
10. 同时审核、重复批准和重新提交均不重复开通、不覆盖已审核提交。
11. 商品新增、编辑、草稿、复制、采集和导入均正确保存所属商户；失效项可回显。
12. 停用商户后各购买入口拦截新业务，存量履约与售后仍可处理，恢复不自动上架旧下架商品。
13. 商户候选、详情、历史、统计、导出及附件下载无跨商户越权，敏感前后值正确脱敏。
14. 历史订单、主体和合同引用不随当前资料变化；未有历史材料时不伪造补齐。
15. 跨店支付及退款分摊一致，采购入库和代发分别记账，不重复产生应付。
16. 迁移重入不创建第二个平台默认商户，不重置已有账号权限或新商品归属。
