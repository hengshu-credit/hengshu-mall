# 后台页面加载优化

范围：仅调整前端读取请求的启动时机及导出依赖的加载时机。没有修改后端接口、业务请求参数、权限判断、页面模板或样式。

## 变更

- 用户标签、公众号渠道码、客服话术：分类和“全部”列表同时读取。原来等待分类返回后，才以固定的空分类 ID 查询列表。
- 列表仍在分类处理完成后应用，保留分类选择重置、列表赋值和错误提示流程。只编辑分类名称的刷新仍只读分类。如果等待期间筛选参数发生变化，重新读取匹配当前参数的列表，不应用过期预读结果。
- 预读仅属于本次加载，没有跨页面或跨刷新响应缓存；手动刷新、分页和后续进入页面仍获取新数据。
- 通用 XLSX 导出库在调用导出时加载；订单 ExcelJS 库在导出数据就绪后加载。沿用原导出函数，不调整文件内容、格式、表头、分页读取或文件名。

## 验证

本机运行中的源码服务，独立 Chrome 会话，无后台登录或业务写入：

| 检查 | 结果 |
| --- | --- |
| 登录页初始 app.js 解码体积 | 17,382,931 → 16,859,330 字节，减少 523,601 字节 |
| 登录页 app.js 传输量（含资源计时中的响应头开销） | 2,826,109 → 2,664,448 字节，减少 161,661 字节 |
| 三个页面分类/列表请求的启动间隔 | 浏览器隔离接口测试均小于 1 毫秒 |
| 分类延迟 500 ms、列表延迟 200 ms 的受控测试 | 全部返回约 503～511 ms；串行等待需叠加两段延迟 |
| 普通导出、重复导出及订单导出 | 实际下载 XLSX，重新读取并检查中文、数字、布尔值、表头及文件名，通过 |
| 页面外观代码 | 四个修改的 Vue 文件，模板与样式均与修改前完全一致 |
| 生产构建 | 通过，导出代码生成独立异步资源 |

体积为开发构建测量；受控延迟用于验证请求并发，不代表真实后台 API 的响应速度。真实业务账号的全部后台操作没有逐项执行。原始本机数据在忽略目录 `help/dev/.state/admin-loading-*.json`，导出文件和构建日志也在该目录。

回归命令（从仓库根目录运行）：

```powershell
node tests/regression/admin_page_loading.cjs
node tests/regression/config_requests.cjs
node tests/regression/admin_routes.cjs
node tests/regression/admin_console.cjs
node tests/regression/admin_tags_lifecycle.cjs
# 需运行中的 8011 源码服务、可解析的 playwright 包和 Chrome：
node tests/regression/admin_loading_browser.cjs
```

页面方法回归覆盖两种返回顺序、参数保持、分类单独编辑、请求失败、失败重试、筛选变化、分页事件及刷新获取新数据。浏览器测试使用真实构建的页面组件与独立只读接口数据，不操作真实后台业务记录。
